## 1. 核心概念（35 min）

### 1.1 props 是输入，只读

- props 是父组件传给子组件的数据，子组件**不能改**；要改就通过回调让父组件改
- 函数组件每次 render 收到一个新的 props 对象；解构是常见写法
- 改 props 不会触发更新，还会破坏可预测性；React 没有运行时拦截，靠约定 + 不可变
- Vue 对照：Vue props 也是单向，但开发环境会警告直接改 props；React 更依赖自觉

### 1.2 children 就是普通 prop

```tsx
<Card>内容</Card>
// 编译后
jsx(Card, { children: '内容' })
```

- `children?: ReactNode`，可以是元素、字符串、数组，甚至函数（render props）
- **默认插槽 = children；具名插槽 = 多个 ReactNode props；作用域插槽 = 函数 prop**

### 1.3 Vue ↔ React 插槽映射

| Vue | React | 说明 |
|---|---|---|
| `<slot />` | `{children}` | 默认插槽 |
| `<slot name="header" />` | `{header}` prop | 具名插槽 |
| 作用域插槽 `#item="{ user }"` | `renderItem={(user) => ...}` | 子组件把数据传给函数 |
| `$emit('close')` | `onClose` 回调 prop | 事件向上 |
| `v-bind="$attrs"` | `{...rest}` | 属性透传 |
| `provide / inject` | Context（017） | 跨层传递 |

### 1.4 组合优于继承

- React 没有模板继承；用 `children`、具名 props、render props 组合
- children 作为 prop 传入还有性能意义：父组件重渲染时元素引用可能稳定，子组件可 bailout（回扣 006）
- 后续模式课（025）会展开 compound components / render props / HOC

### 1.5 默认值与 TypeScript

```tsx
import type { ReactNode } from 'react'

interface Props {
  title?: string
  children: ReactNode
  footer?: ReactNode
}

function Card({ title = 'Untitled', children, footer }: Props) {
  // ...
}
```

- 函数组件默认值用**默认参数解构**；React 19 已移除函数组件的 `defaultProps`
- `children` 类型用 `ReactNode`（不只 `ReactElement`）
- 可选用 `PropsWithChildren<Props>`，也可以手写 `children?: ReactNode`
- 可选 prop 判断用 `!= null`（007 的坑）

### 1.6 常见坑

- **直接调用组件函数** `{Header()}`：绕过 React 的 render/调和，Hooks 会错乱；必须写 `<Header />`
- props 解构后把剩余属性 spread 到 DOM，可能带出非法属性
- `children` 是函数时，类型要显式声明为 `(data: T) => ReactNode`
- `key`、`ref` 不是普通 props：key 由 `jsx()` 第三参传入；React 19 中 ref 可作为 prop

### 今日一句话总结
