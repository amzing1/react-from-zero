## 1. 核心概念（20 min，项目课压缩讲）

### 1.1 状态设计：单一数据源 + 派生数据

只把**用户输入**放进 state：

```tsx
const [keyword, setKeyword] = useState('')
const [selectedTag, setSelectedTag] = useState('全部')
```

其他都派生：

```tsx
const tags = ['全部', ...new Set(notes.flatMap((n) => n.tags))]
const filteredNotes = notes.filter((note) => {
  const matchKeyword =
    note.title.toLowerCase().includes(keyword.trim().toLowerCase()) ||
    note.content.toLowerCase().includes(keyword.trim().toLowerCase())
  const matchTag = selectedTag === '全部' || note.tags.includes(selectedTag)
  return matchKeyword && matchTag
})
```

**不要把 `filteredNotes` 放进 useState**：那会产生两份数据，搜索词、标签、笔记列表任意一个变化都要手动同步，迟早不同步。

过滤逻辑写成**纯函数**更好，后续可以直接测：

```tsx
function filterNotes(notes: Note[], keyword: string, tag: string): Note[]
```

### 1.2 组件边界

```text
NoteBoard（容器：持有 state，计算派生数据）
├── SearchBar（受控输入）
├── TagFilter（标签 + 选中态）
├── NoteList（map + key；空状态）
│   └── NoteCard（单张卡片）
└── EmptyState（无结果 + 清除筛选）
```

- **props 向下，回调向上**：子组件不持有过滤状态
- 组件不要过度拆分，一个文件一个主组件
- 展示组件只负责渲染，过滤逻辑集中在一处

### 1.3 列表与条件渲染

- `key={note.id}`，不用 index
- 空状态放在 `NoteList`：`notes.length === 0 ? <EmptyState /> : map`
- 标签列表去重：`new Set(notes.flatMap((n) => n.tags))`
- 搜索 + 标签是 **AND** 关系
- 「全部」标签重置标签筛选；清除筛选同时清空 keyword 和 selectedTag

### 1.4 CSS Modules

```tsx
import styles from './NoteBoard.module.css'

<main className={styles.board}>...</main>
```

- Vite 原生支持 `*.module.css`；类名局部化，避免全局污染
- 全局样式放 `src/index.css`（已提供 reset）
- 响应式：`grid-template-columns: repeat(auto-fill, minmax(240px, 1fr))`
- 可访问性：搜索框加 `label` 或 `aria-label`；标签用 `<button aria-pressed>`；保留 focus 样式

### 1.5 面试/工作落地点

- 什么该放 state、什么该派生？冗余 state 的典型 bug
- 列表 key 的选择
- 受控输入与非受控输入
- 组件职责边界与 props 设计
- 可访问性的最低要求
