## 1. 核心概念（35 min）

### 1.1 render 与 commit：两个阶段

| 阶段 | 做什么 | 能否中断 | 执行次数（开发 StrictMode） |
|---|---|---|---|
| **Render** | 调用组件函数，生成新元素树；与 current fiber 树 reconcile；给 fiber 打 flags | 可以（并发渲染） | 2 次 |
| **Commit** | 按 flags 同步操作 DOM；执行 layout effects；再执行 passive effects | 不可以 | 1 次 |

**Commit 子阶段**（函数组件相关）：

1. **beforeMutation**：`getSnapshotBeforeUpdate`（类组件）；函数组件少用
2. **mutation**：DOM 增删改；`useInsertionEffect`
3. **layout**：`useLayoutEffect`、ref 挂载；**绘制前同步执行**
4. **passive**：`useEffect`；**绘制后异步执行**

### 1.2 纯函数

组件是 `UI = f(props, state)`：相同输入必须得到相同输出。

**Render 里不能做**：

- 改外部变量、改 props/state
- 发请求、操作 DOM、读写 localStorage
- `Date.now()` / `Math.random()`（除非输入稳定）
- 订阅、定时器（放 Effect）

**为什么必须纯**：

- 可缓存、可中断、可重启、可丢弃（并发渲染的前提）
- StrictMode 敢双调用，用来暴露不纯
- Compiler 的自动 memo 依赖纯性

Vue 对照：Vue 的 render 也应是纯的，但模板 + 响应式让副作用更隐蔽；React 把组件函数直接交给你，纯性要求更显式。

### 1.3 StrictMode 的行为

- **开发环境**：render 双调用；Effect 首次挂载执行 `setup → cleanup → setup`；**commit 只有一次**
- **生产环境**：不双调用
- 不双调用：事件处理函数；不双 commit
- 目的：暴露不纯 render、缺失的 cleanup

### 1.4 快照与批处理

- 每次 render 的 props/state 是**常量快照**；事件处理闭包捕获当次 render 的快照
- `setState` 不改变当前变量，只把更新排队；事件处理结束后统一 render（自动批处理）
- `setN(n + 1)` 基于闭包旧值；`setN(x => x + 1)` 基于队列中的最新值
- `flushSync` 可以强制同步刷新（014 展开）

### 1.5 日志实验的预期

一次点击大致是：

```text
[render] 组件函数执行（StrictMode 下可能 2 次）
[layout] useLayoutEffect（绘制前）
（浏览器绘制）
[effect] useEffect（绘制后）
```

首次挂载在 StrictMode 下：

```text
[render] ×2
[layout] setup → cleanup → setup
[effect] setup → cleanup → setup
```

### 我的实现 / 遇到的问题

已完成 `src/components/day009/`：`RenderCommitLab` / `ImpureDemo` / `SnapshotDemo`。

**RenderCommitLab 实测日志：**

- 挂载 render：Parent ×2 → Child ×2（StrictMode 每个组件连续双调用）
- 挂载 layout / effect：Child → Parent（子先父后）
- StrictMode 额外循环：cleanup 为 Parent → Child（父先子后），再 setup 一遍
- 点 Parent +：只 render Parent ×2；Child 完全不动（children 引用稳定 → 子树 bailout）
- 点 Child +：只 render Child ×2；Parent 完全不动（更新只影响拥有者及子树）

**ImpureDemo：** dev 初始 2、每次 +2；build 初始 1、每次 +1；纯版本 dev/build 一致。

**SnapshotDemo：** 按钮 1 打印旧快照 0；按钮 2 最终 1；按钮 3 最终 3；三次 setState 批处理为一次 render 阶段/一次 commit，dev 下函数体执行两次。

### 今日一句话总结

render 是算 UI（可中断、必须纯、开发环境双调用），commit 是改 DOM（同步、一次、四子阶段 beforeMutation → mutation → layout → passive）；state 是快照，setState 只排队，更新函数拿队列里的最新值。
