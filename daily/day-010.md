## 1. 核心概念（35 min）

### 1.1 条件渲染

```tsx
// 提前 return
if (!user) return null

// 三元
{isLoading ? <Spinner /> : <List />}

// &&
{count > 0 && <Badge count={count} />}   // 注意 0 的坑

// 计算好再渲染
const content = isError ? <Error /> : <List />
```

**卸载 vs CSS 隐藏**：

| 方式 | DOM | state | Effect |
|---|---|---|---|
| 条件渲染（不渲染） | 移除 | 丢失 | cleanup 执行 |
| `style={{ display: 'none' }}` | 保留 | 保留 | 不执行 cleanup |

Vue 对照：`v-if` vs `v-show`。

**用 key 重置 state**：

```tsx
<ProfileForm key={userId} user={user} />
```

key 变化 → React 卸载旧组件、挂载新组件 → 内部 state 和 Effect 全部重置。这是“切换用户清空表单”的标准写法。

**Hooks 规则**：不能条件调用 Hooks；提前 return 必须放在所有 Hooks 之后。

### 1.2 列表与 key

```tsx
{items.map((item) => (
  <li key={item.id}>{item.name}</li>
))}
```

key 的规则：

- **唯一**：同一层级兄弟之间唯一
- **稳定**：跨 render 不变；不要用 `Math.random()` / `Date.now()`
- **可预测**：最好用数据 id
- **不进 props**：`props.key` 是 `undefined`；key 由 `jsx()` 第三参传入
- 列表项是 Fragment 时，用 `<Fragment key={id}>`

**index key 的问题**：

```tsx
{items.map((item, index) => (
  <li key={index}>{item.name}</li>
))}
```

React 用 key 匹配“上一次的谁”和“这一次的谁”。用 index 时，key 表示的是**位置**，不是**身份**：

- 在头部插入一项 → 所有位置后移，React 认为每个位置的内容都变了
- 重排/删除 → DOM 和组件 state 会跟着“位置”走，而不是跟着数据走
- 典型症状：输入框内容错位、checkbox 勾选错位、动画错乱

**什么时候可以用 index**：列表静态、不重排、不增删、没有内部 state。即便这样也建议用 id，避免以后改动踩坑。

### 1.3 React 事件系统

**合成事件（SyntheticEvent）**：

- React 包装原生事件，提供跨浏览器一致的接口
- `e.nativeEvent` 拿原生事件
- React 17 起**移除了事件池**，不需要 `e.persist()`

**事件委托**：

- React 17+ 把监听器挂在**根容器**（`createRoot` 的 DOM 节点）上，不是 `document`
- 事件沿 **React 组件树**冒泡（包括 portal），不一定沿 DOM 树
- 优点：减少监听器、统一管理、多版本 React 共存

**常用操作**：

```tsx
<button onClick={handleClick}>          // 传引用
<button onClick={() => handle(id)}>     // 传参
<form onSubmit={(e) => e.preventDefault()}>
<div onClickCapture={...}>              // 捕获阶段
e.stopPropagation()                     // 阻止继续冒泡
e.preventDefault()                      // 阻止默认行为
e.target                                // 触发事件的元素
e.currentTarget                         // 当前处理函数绑定的元素
```

**注意**：

- `onChange` 在 React 里等价于原生 `input` 事件，每次输入都触发
- 事件处理里的多次 setState 会被批处理
- Vue 的 `.stop` / `.prevent` / `.capture` 对应 `stopPropagation` / `preventDefault` / `onXxxCapture`

### 1.4 Vue 对照

| Vue | React |
|---|---|
| `v-if` | 条件 return / 三元 / `&&` |
| `v-show` | `style={{ display: 'none' }}` |
| `v-for` + `:key` | `map` + `key` |
| `@click` | `onClick` |
| `@click.stop` | `e.stopPropagation()` |
| `@submit.prevent` | `e.preventDefault()` |
| `@click.capture` | `onClickCapture` |
| `@keyup.enter` | `onKeyDown` + `e.key === 'Enter'` |
| `v-model` | `value` + `onChange`（015 展开） |
| key 变化强制重建 | 同 |

### 我的实现 / 遇到的问题

已完成 `src/components/day010/`：`KeyLab` / `ResetWithKey` / `EventLab`。

**KeyLab 实测：**

- 左列表 `key={index}`：输入内容后反转，输入框内容留在原位置，看起来「没反应」——React 按 key 匹配位置，复用了同一批 DOM/state
- 右列表 `key={item.id}`：DOM 节点和输入值随 item 移动，反转正确
- 控制台无 key warning：index key 合法但语义错误

**ResetWithKey 实测：**

- 无 key：切换用户后输入框内容残留（同一组件实例，state 保留）
- 有 key：切换用户触发卸载/重挂载，state 重置
- 输入改为受控 `value={name}`，证明重置的是 state

**EventLab 实测：**

- capture：外 → 里；bubble：里 → 外
- `stopPropagation`：截断后续 bubble；祖先 capture 已执行
- `preventDefault`：阻止链接跳转，但不阻止冒泡

## 4. 总结与复习卡（10 min）

### 今日一句话总结

key 是身份不是位置：index key 在重排时会把「位置」当身份，复用错 DOM/state；事件委托挂在根容器，capture 外→里、bubble 里→外，stopPropagation 截断传播，preventDefault 只挡默认行为。
