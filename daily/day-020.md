## 1. 核心概念（35 min）

### 1.1 心智模型：Effect 是同步，不是生命周期

- `useEffect(setup, deps)`：组件渲染并提交后，把组件与某个**外部系统**同步
- 外部系统：订阅（WebSocket、事件）、定时器、DOM API、网络请求、第三方库
- Effect 不是 `mounted` / `updated`：每次依赖变化都会"清理上一次同步，再建立新同步"
- **能在 render 或事件处理里做的事，不要放 Effect**（派生数据、用户点击触发的请求）
  - 这一条 021 会展开："你可能不需要 Effect"

```tsx
useEffect(() => {
  const connection = createConnection(roomId)
  connection.connect()
  return () => connection.disconnect()
}, [roomId])
```

### 1.2 执行时机

- render → commit（DOM 更新）→ 浏览器绘制 → **useEffect**（通常绘制后）
- 交互触发的更新，React 可能在绘制前执行 Effect；不要依赖精确的绘制时序
- `useLayoutEffect`：commit 后、绘制前执行，会阻塞绘制；只用于布局测量/同步 DOM
- StrictMode（开发环境）：挂载时 **setup → cleanup → setup**，用于暴露缺失的清理；生产环境只 setup 一次
- Day 009 实测：挂载 setup 子先父后，卸载 cleanup 父先子后；跨组件顺序不要当业务契约

### 1.3 依赖数组

| 写法 | 行为 |
|---|---|
| 不传 | 每次 render 后都执行 |
| `[]` | 只在挂载后执行（StrictMode 开发环境两次） |
| `[a, b]` | 每次 render 后，任一依赖与上一次不同（`Object.is`）才执行 |

- React 逐项用 **`Object.is`** 比较本次与上次的依赖；数组长度必须稳定
- 依赖不是"触发器"，而是"这个 Effect 用到的、会变化的响应式值"
- 必须列全：props、state，以及由它们派生的值；**ref.current 不是响应式依赖**
- 内联对象 / 数组 / 函数每次 render 都是新引用 → Effect 每次都跑
  - 解法：把定义移到 Effect 内部 / 组件外；或 `useMemo` / `useCallback` 稳定引用；或 021 的 `useEffectEvent`
- 不要为了"只跑一次"而欺骗依赖数组（漏依赖 + lint 屏蔽）→ 闭包读到旧值

### 1.4 cleanup

- cleanup 在**下一次 setup 之前**执行（依赖变化时），以及**卸载时**执行一次
- 清理对象：定时器、订阅、事件监听、请求、第三方实例
- cleanup 必须能访问到本次 setup 创建的资源（闭包）
- 没有 cleanup 的后果：重复订阅、定时器泄漏、旧请求回写、StrictMode 下问题翻倍
- cleanup 不是"卸载钩子"：依赖变化时也会执行

```tsx
useEffect(() => {
  function onResize() {
    setWidth(window.innerWidth)
  }
  window.addEventListener('resize', onResize)
  return () => window.removeEventListener('resize', onResize)
}, [])
```

### 1.5 闭包陷阱（stale closure）

```tsx
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1) // ❌ 闭包里的 count 永远是挂载时的 0
  }, 1000)
  return () => clearInterval(id)
}, []) // 漏了 count
```

- 每次 render 都会创建新的闭包；`[]` 让 Effect 只保留第一次的闭包
- 三种解法：
  1. **函数式更新**：`setCount(c => c + 1)`（不依赖外部 count）
  2. **补依赖**：`[count]`，但会销毁/重建定时器，计时被重置
  3. **ref 保存最新值** 或 021 的 `useEffectEvent`（读最新值但不作为依赖）
- 核心：**不能既漏依赖又期望拿到最新值**

### 1.6 请求竞态

- 场景：`userId` 从 1 快速切到 2；请求 1 慢、请求 2 快；请求 1 后返回，覆盖了请求 2 的结果
- cleanup 只保证"下一次 Effect 前执行"，**不会自动取消请求**

```tsx
useEffect(() => {
  let ignore = false

  async function load() {
    const data = await fetchUser(userId)
    if (!ignore) setUser(data)
  }
  load()

  return () => {
    ignore = true
  }
}, [userId])
```

- `ignore` flag：不取消请求，只阻止旧响应写入状态
- `AbortController`：真正取消请求

```tsx
useEffect(() => {
  const controller = new AbortController()

  fetch(`/api/users/${userId}`, { signal: controller.signal })
    .then((res) => res.json())
    .then((data) => setUser(data))
    .catch((error) => {
      if (error.name !== 'AbortError') setError(error)
    })

  return () => controller.abort()
}, [userId])
```

- 不要在 Effect 里直接写 `async`：返回值会变成 Promise，React 无法当 cleanup

```tsx
// ❌
useEffect(async () => { ... }, [])
// ✅ 内部定义 async 函数并调用
```

### 1.7 Effect vs 事件处理

| 事情发生的时机 | 放哪 |
|---|---|
| 用户点击/提交导致 | 事件处理函数 |
| 组件出现/参数变化后要同步外部系统 | Effect |
| 能从 props/state 算出来 | render 派生，不进 state、不进 Effect |
| 组件卸载/依赖变化要清理 | Effect cleanup |

### 1.8 Vue 对照

| Vue | React | 关键差异 |
|---|---|---|
| `watch(source, cb)` | `useEffect(setup, [deps])` | Vue 显式声明 source；React 手动声明 deps，`Object.is` 比较 |
| `watchEffect(cb)` | 无直接等价 | Vue 自动追踪依赖；React 必须列 deps |
| `watch(..., { immediate: true })` | 默认挂载后执行 | React Effect 没有"非立即"模式 |
| `onMounted` / `onUnmounted` | `useEffect(..., [])` + cleanup | React 用同一套机制 |
| watch 回调的 `onCleanup` | Effect 的 cleanup | 时机类似：下一次执行前 |
| `flush: 'post'` | `useEffect`（绘制后） | 大体对应 |
| `nextTick` | `useLayoutEffect` / commit 后读 ref | React 没有 nextTick |
| 自动依赖追踪 | 手动依赖数组 | React 可能因引用变化多跑，Vue 按属性依赖触发 |

**关键差异**：Vue 的 `watchEffect` 自动收集依赖，`watch` 只在 source 变化时触发；React 没有自动追踪，靠你列依赖，且对象/函数引用变化也算变化。

### 1.9 常见坑

1. 漏依赖 / 屏蔽 lint → 闭包读到旧值
2. 内联对象/函数作为依赖 → Effect 每次执行，甚至无限循环
3. Effect 里无条件 `setState` → 无限循环
4. 订阅/定时器/请求没有 cleanup → 泄漏、重复、竞态
5. `useEffect(async () => ...)` → 返回 Promise，不是 cleanup
6. 依赖用 `[]` 但 Effect 里用了 props/state → 永远读初始值
7. 用 Effect 同步派生状态（如把过滤结果写进 state）→ 多一次渲染、容易不同步；render 派生即可
8. 以为 cleanup 只在卸载时执行 → 依赖变化时也执行
9. StrictMode 双挂载 → 请求发两次；用 cleanup/ignore 处理，不要移除 StrictMode
10. `useLayoutEffect` 在 SSR 下警告；非布局场景用 `useEffect`
