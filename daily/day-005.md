## 1. 核心概念（35 min）

### 1.1 心智模型：一个前端项目有五层基线

| 层 | 本项目选型 | 职责 | 失败时的症状 |
|---|---|---|---|
| 运行时 | Node 24+ / pnpm | 装依赖、跑脚本 | 依赖装不上、脚本跑不了 |
| 构建 | Vite 8 + @vitejs/plugin-react 6（Oxc） | 转换、HMR、打包 | 页面白屏、构建产物异常 |
| 类型 | TypeScript 7（project references） | 静态检查、编辑器提示 | 编辑器报红 / CI 类型检查失败 |
| 质量 | oxlint + Prettier | 规则检查、格式统一 | review 噪音、低级 bug |
| 调试 | React DevTools + sourcemap | 定位重渲染、错误栈 | 「知道有 bug 但找不到」 |

**心法**：这五层要能独立执行、独立排错。`lint` 不负责类型，`typecheck` 不负责风格，`build` 不应是唯一的检查入口。

### 1.2 Vite 的 dev 与 build 是两条链

**dev（`vite`）**

- 启动时只做依赖预构建（optimizeDeps），把第三方依赖转成 ESM 并缓存到 `node_modules/.vite`
- 浏览器请求哪个模块，就按需转换哪个模块（TS → JS、JSX → JS），以原生 ESM 返回，**不打包**
- HMR 按模块边界替换；React 侧由 plugin-react 提供 Fast Refresh（改组件通常保留 state，改 Hook 签名等会整块刷新）
- 因此 dev 启动快、单文件更新快，但与生产行为存在差异：无 tree-shaking、无压缩、`import.meta.env.DEV` 为 true、React 处于开发模式（StrictMode 双调用）

**build（`vite build`，本项目脚本为 `tsc -b && vite build`）**

- 打包、tree-shaking、代码分割、压缩、资源哈希
- `vite preview` 只是本地静态服务器，不是生产服务器
- 生产环境 React 走 production 构建：无双调用、无开发警告、性能更高

**Vue 对照**：同一套 Vite；差异在插件——Vue 用 `@vitejs/plugin-vue` 编译 SFC，React 用 `@vitejs/plugin-react` 做 JSX 转换与 Fast Refresh。HMR 思路一致：模块级替换 + 组件状态尽量保留。

> 版本核对项：本地 `vite@8.x` 的构建内核（Rolldown）与 dev 转换器（Oxc）以 `pnpm list vite @vitejs/plugin-react` 和官方文档为准，课后记录。

### 1.3 TypeScript 工程基线

**project references**

- 根 `tsconfig.json` 是空壳（`files: []` + `references`），把「浏览器代码」和「Node 侧配置」拆成两个项目
- `tsconfig.app.json`：`lib: ["ES2023", "DOM"]`、`jsx: react-jsx`、include `src`
- `tsconfig.node.json`：`lib: ["ES2023"]`、`types: ["node"]`、include `vite.config.ts`
- `tsc -b` 按引用图增量检查；改了哪个项目只重查哪个

**本项目当前缺口**：`tsconfig.app.json` 里**没有 `strict`**（默认 false）。今天要补上。

**`strict` 家族**：`noImplicitAny`、`strictNullChecks`、`strictFunctionTypes`、`strictBindCallApply`、`strictPropertyInitialization`、`noImplicitThis`、`alwaysStrict`、`useUnknownInCatchVariables`。

**值得单独决策的选项**

| 选项 | 作用 | 代价 / 建议 |
|---|---|---|
| `noUncheckedIndexedAccess` | 索引访问返回 `T \| undefined` | 更安全，但老代码迁移噪音大；新项目建议开 |
| `exactOptionalPropertyTypes` | 可选属性不允许显式赋 `undefined` | 最严格，第三方类型常不兼容；按团队情况 |
| `verbatimModuleSyntax` | 类型导入必须写 `import type` | 单文件转译（Oxc/esbuild/SWC）下保证类型导入被擦除；本项目已开 |
| `erasableSyntaxOnly` | 禁止 `enum`、`namespace` 等需要运行时代码的语法 | 与 Node 类型剥离 / 单文件转译对齐；本项目已开 |

**路径别名为什么必须配两份**

- `tsconfig` 的 `paths` 只影响**类型解析**，不会重写 import 语句
- Vite 的 `resolve.alias` 才影响**运行时 / 构建解析**
- 只配 tsconfig：编辑器不报错，但 dev 直接 `Failed to resolve import`
- 只配 Vite：能跑，但 tsc 类型检查报错、编辑器无提示

```jsonc
// tsconfig.app.json
"paths": { "@/*": ["./src/*"] }
```

```ts
// vite.config.ts
import path from "node:path";
import react from "@vitejs/plugin-react";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { "@": path.resolve(import.meta.dirname, "src") },
  },
});
```

### 1.4 质量层：2026 年的 lint / format 选型

| 工具 | 定位 | 优势 | 边界 |
|---|---|---|---|
| oxlint | Rust linter | 极快、零配置起步、Vite 模板默认；有 react/rules-of-hooks 等规则 | 插件生态和类型感知规则少于 ESLint（类型感知需 `oxlint-tsgolint`） |
| ESLint（flat config）+ typescript-eslint | 事实标准 | 生态最全、类型感知规则成熟 | 慢、配置重 |
| Biome | Rust 全家桶 | lint + format 一体、快 | React 专项规则较少 |
| Prettier | 格式化 | 事实标准、编辑器集成好 | 只做格式，不管逻辑 |

**本课决定**：延续 Day 001 的 oxlint（不推翻已有基线），格式化补 Prettier；需要类型感知的规则时再加 `oxlint-tsgolint` 或局部引入 ESLint。不要同时上两套 formatter。

**脚本分层**

```jsonc
{
  "dev": "vite",
  "build": "tsc -b && vite build",
  "preview": "vite preview",
  "typecheck": "tsc -b",
  "lint": "oxlint",
  "format": "prettier --write .",
  "format:check": "prettier --check ."
}
```

### 1.5 环境变量

- Vite 从 `.env`、`.env.local`、`.env.[mode]` 读取；只有 `VITE_` 前缀会暴露给客户端
- `.env.example` 提交；`.env.local` 不提交（本项目 `.gitignore` 已有 `*.local`）
- 类型补全写在 `src/vite-env.d.ts` 的 `ImportMetaEnv` 接口里

```ts
// src/vite-env.d.ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_APP_TITLE: string;
}

interface ImportMeta {
  readonly env: ImportMetaEnv;
}
```

> 实验项：故意写错变量名，观察 `vite/client` 是否带索引签名、tsc 是否报错——把结论记下来。

### 1.6 调试：React DevTools 与 sourcemap

**React DevTools**

- Components：组件树、props / hooks、Owner（19.1 起有 Owner Stack，`captureOwnerStack()`）
- Settings → **Highlight updates when components render**：页面操作时闪烁的组件 = 发生重渲染的组件
- Profiler：录制一次交互，看 flamegraph / ranked，点组件看 **Why did this render?**（props / state / context / hooks changed）

**sourcemap 策略**

| 场景 | 配置 | 说明 |
|---|---|---|
| dev | 默认开启 | 断点直接落在 TS/TSX 源码 |
| 生产 + 错误监控 | `build.sourcemap: "hidden"` | 生成 .map 但不加 `sourceMappingURL` 注释，私有上传给 Sentry 等 |
| 公共开源站点 | `true` 可接受 | 接受源码可见 |
| 不想暴露源码 | `false` | 错误栈只有压缩后的行列号 |

**StrictMode 提醒**：dev 的双 render / Effect 双执行是刻意设计，不要用 build 行为去「验证」它，也不要把 dev 的双日志当 bug。

### 1.7 目录与命名约定

- 小项目可按类型：`components/ hooks/ lib/ types.ts`
- 中大型按 feature：`features/<name>/{components,hooks,api,types.ts}` + `shared/`
- 就近放置（colocation）：测试、样式、类型跟组件放一起
- 谨慎使用 barrel（`index.ts` 汇总导出）：会拖慢 dev 启动、引入循环依赖、削弱 tree-shaking
- 学习项目保留 `components/dayXXX` 作为历史记录；新代码按约定组织

### 1.8 Vue 对照

| Vue 生态 | React 生态 | 关键差异 |
|---|---|---|
| Vite + @vitejs/plugin-vue | Vite + @vitejs/plugin-react | SFC 编译 vs JSX 转换；HMR 思路一致 |
| vue-tsc | tsc -b | Vue 模板类型要靠 vue-tsc；React 的 JSX 由 tsc 直接检查 |
| `@/` alias（vite + tsconfig） | 相同 | 都是双份配置，原理一致 |
| ESLint + eslint-plugin-vue | oxlint / ESLint + react 插件 | Vue 规则偏模板；React 重点是 Hooks 规则 |
| Prettier | Prettier | 相同 |
| Vue DevTools | React DevTools | React 的 Profiler / Highlight updates 是定位重渲染主力 |
| unplugin-auto-import | 少见 | React 生态倾向显式 import，利于可读性与类型 |
| `.env` + `VITE_` | 相同 | 同一套机制 |

**Q1｜Vite 两条链** ⚠️
- 依赖预构建：CJS/UMD → ESM、合并大量小文件减少请求 ✅
- dev 按需转换、不打包 ✅
- **build 内核是 Rolldown，不是 Rollup**；dev 转换器是 Oxc
- 差异补充：dev 无 tree-shaking/压缩/哈希、有 HMR、React 开发模式（StrictMode 双调用）；build 走 production React、无开发警告

**Q2｜别名** ✅
只配 `paths`：类型通过、dev 运行时报 `Failed to resolve import`；只配 `alias`：dev 能跑、`tsc` 报错。

**Q3｜strict** ⚠️
- `strict` 包含：`noImplicitAny`、`strictNullChecks`、`strictFunctionTypes`、`strictBindCallApply`、`strictPropertyInitialization`、`noImplicitThis`、`alwaysStrict`、`useUnknownInCatchVariables`
- 答成“不能对 null/undefined 取属性”是 `strictNullChecks`
- `noUncheckedIndexedAccess` 不在 `strict` 内：索引访问返回 `T | undefined`；收益是避免越界/缺失键被当成 T，成本是额外检查和迁移噪音

**Q4｜类型导入** ❌
- `verbatimModuleSyntax`：import/export 原样输出，类型导入必须写 `import type`；否则单文件转译时类型导入会残留为运行时 import
- `erasableSyntaxOnly`：只允许可擦除语法，禁止 `enum`、运行时 `namespace`、构造函数参数属性、`import =`；与 Node 类型剥离 / Oxc 单文件转译对齐

**Q5｜调试** ✅
- 生产 + 错误监控：`build.sourcemap: 'hidden'`，生成 `.map` 但不加注释，私有上传 Sentry
- DevTools：Highlight updates 找重渲染组件；Profiler 录制、看 commit、点组件条看原因
- Context：内联 value 每次 Provider 渲染都是新对象，所有消费者重渲染 ✅
