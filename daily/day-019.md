## 1. 核心概念（35 min）

### 1.1 useRef 是什么

```tsx
const countRef = useRef(0) // { current: 0 }
```

- 返回的是**同一个对象**，跨每次 render 持久；写 `.current` 只改盒子内容，**不通知 React**
- 两个用途：DOM 引用；保存不参与渲染的实例值（定时器 id、上一次的值、第三方实例）
- 不要用它存需要展示的数据——UI 不会更新

```tsx
const countRef = useRef(0)
const [renderCount, setRenderCount] = useState(0)

// 事件里改 ref：不触发渲染
countRef.current += 1

// 改 state 才触发渲染；渲染时才能看到 ref 的最新值
setRenderCount((n) => n + 1)
```

### 1.2 state / ref / 普通变量

| | 触发渲染 | 跨 render 持久 | 可变 | 适合 |
|---|---|---|---|---|
| state | ✅ | ✅ | 必须不可变更新 | 参与 UI 的数据 |
| ref | ❌ | ✅ | 可以原地改 | DOM 节点、定时器、非 UI 值 |
| 普通变量 | ❌ | ❌ | 随便 | 单次 render 的临时计算 |

判断：**出现在 JSX 里的数据 → state；只给事件 / Effect 用的 → ref**。

### 1.3 渲染期间不要读写 ref

- render 必须是纯函数；读写 `ref.current` 是副作用
- 首次 render 时 DOM ref 还是 `null`；后续 render 读到的也可能是旧值
- 例外：惰性初始化（`if (ref.current === null) ref.current = new Thing()`）可以，但要谨慎
- 事件处理、Effect、ref callback 里读写是安全的

### 1.4 DOM ref

```tsx
const inputRef = useRef<HTMLInputElement>(null)

<input ref={inputRef} />
<button onClick={() => inputRef.current?.focus()}>聚焦</button>
```

- React 在 **commit 阶段**把 DOM 节点写进 `ref.current`（DOM 更新后、浏览器绘制前）；卸载时置回 `null`
- 首次 render 期间是 `null`，所以不要在 render 里 `inputRef.current.focus()`
- 常见操作：`focus()`、`select()`、`scrollIntoView()`、`getBoundingClientRect()`、`video.play()/pause()`
- 类型：`useRef<HTMLInputElement>(null)` 在 React 19 类型里是 `RefObject<HTMLInputElement | null>`；`ref` prop 接受 `Ref<T>`

### 1.5 ref callback 与 React 19 cleanup

```tsx
<div
  ref={(node) => {
    console.log('attach', node)
    return () => console.log('detach', node)
  }}
/>
```

- ref callback 在挂载/更新时调用；React 19 支持**返回清理函数**，卸载时调用清理，而不是再传 `null`
- 适合：动态列表节点、第三方库初始化/销毁（chart、editor 等）
- StrictMode 开发环境会模拟挂载/卸载，callback 多跑一轮；有 cleanup 时是 setup → cleanup → setup
- 注意：callback 要写成块体；返回非函数值会被类型防呆挡下

### 1.6 useImperativeHandle

```tsx
type FancyInputHandle = {
  focus: () => void
  clear: () => void
}

function FancyInput({ ref }: { ref?: Ref<FancyInputHandle> }) {
  const inputRef = useRef<HTMLInputElement>(null)
  const [value, setValue] = useState('')

  useImperativeHandle(
    ref,
    () => ({
      focus: () => inputRef.current?.focus(),
      clear: () => setValue(''),
    }),
    [],
  )

  return (
    <input
      ref={inputRef}
      value={value}
      onChange={(e) => setValue(e.target.value)}
    />
  )
}
```

- 父组件拿到的是**自定义 handle**，不是 DOM 节点
- 依赖数组像 `useMemo`；handle 里用到会变的 props/state 要进依赖
- 它是**逃生舱**：能通过 props/state/回调表达就别用；适合弹窗、播放器、编辑器、表单校验等命令式 API
- React 19：函数组件直接把 `ref` 当普通 prop 接收，**不需要 `forwardRef`**（仍兼容旧写法）

### 1.7 React 19 ref-as-prop

```tsx
// React 19：ref 是普通 prop
function Input({ ref, ...props }: ComponentPropsWithRef<'input'>) {
  return <input ref={ref} {...props} />
}
```

- 18 及以前需要 `forwardRef((props, ref) => ...)`
- 19 的 `useImperativeHandle` 可以直接接收 `ref` prop
- 迁移建议：新代码用 ref-as-prop；库代码保留 `forwardRef` 兼容旧版本

### 1.8 Vue 对照

| Vue | React | 关键差异 |
|---|---|---|
| `const el = ref(null)` + `ref="el"` | `useRef` + `ref={el}` | Vue 的 `ref()` 是响应式数据；React 的 `useRef` 不触发渲染 |
| `$refs` | 每个 ref 变量 | 没有集中式 `$refs` 对象 |
| `defineExpose({ focus })` | `useImperativeHandle` / ref-as-prop | React 需显式声明暴露的 handle |
| `nextTick(() => el.value...)` | `useLayoutEffect` / `useEffect` 里读 ref | React 没有 nextTick；commit 后 ref 就绪 |
| `watch(el, ...)` | ref callback | 节点变化用 callback 监听 |
| 自定义指令拿到 el | ref callback / Effect | 用组合表达行为 |

- Vue 的 `ref()` 与 React 的 `useRef` **同名不同义**：前者是响应式引用，后者是可变盒子
- Vue 模板 ref 在挂载后可读；React 在首次 render 期间还是 `null`，要等 commit

### 1.9 常见坑

1. 在 render 里读/写 `ref.current` → 不纯、首次为 `null`、可能读到旧值
2. 把要展示的数据放 ref → UI 不更新
3. `useRef(expensive())` 每次 render 都会执行参数（没有惰性初始化重载）
4. 自定义组件没把 ref 透传 → 父级 ref 为 `null`（React 19 需把 ref 当 prop 接住）
5. 在 ref callback 里做需要清理的副作用却不返回 cleanup → 泄漏
6. `useImperativeHandle` 依赖数组漏项 → handle 里闭包读到旧值
7. 依赖 ref 做条件渲染 → 永远不会触发渲染
8. 认为 ref 和 state 一样会自动同步 → ref 是手动管理的

## 4. 总结与复习卡（10 min）

### 今日一句话总结

ref 是跨 render 持久的可变盒子，改它不触发渲染；DOM ref 在 commit 后可用，要展示 ref 的值必须走 state 快照；ref-as-prop + useImperativeHandle 是命令式逃生舱，外部状态（媒体）要用事件同步而不是手动 toggle。
