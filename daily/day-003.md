## 1. 核心概念（35 min）

### 1.1 组件即函数：props 是唯一输入

- Vue：SFC + `defineProps`，模板自动解包，props 响应式
- React：函数组件，props 是**每次渲染的快照**，只读
- 单向数据流：数据向下传、事件向上走；React 没有 `emit`，用**回调 prop** 代替
- 不要在 render 期间调用回调或修改 props

### 1.2 emit → callback props

```tsx
// React
type UserCardProps = {
  user: User
  onEdit: (user: User) => void
  onDelete: (id: string) => void
}
```

- 命名约定 `onXxx`，父组件传入函数
- Vue 的 `emit('save', user)` → React 的 `onSave(user)`，在事件处理函数里调用

### 1.3 slots → children / ReactNode props / render props

| Vue | React | 说明 |
|---|---|---|
| 默认插槽 `<slot />` | `children` | `children: ReactNode` |
| 具名插槽 `<slot name="header" />` | `header: ReactNode` prop | 用普通 prop 传 JSX |
| 作用域插槽 `v-slot="{ user }"` | `renderActions?: (user) => ReactNode` / 函数 children | 函数作为 prop 传递 |
| 动态插槽名 | 任意 ReactNode prop | 没有专门的插槽语法 |

### 1.4 provide / inject → Context

```tsx
const ThemeContext = createContext<Theme | undefined>(undefined)

function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light")
  return <ThemeContext value={theme}>{children}</ThemeContext>
}

function useTheme() {
  const ctx = useContext(ThemeContext)
  if (ctx === undefined) throw new Error("useTheme must be used within ThemeProvider")
  return ctx
}
```

- React 19 可以直接用 `<Context>` 作为 Provider（不必写 `<Context.Provider>`）
- Context value 变化 → 所有消费者重渲染；value 是新对象时尤其要注意
- 与 Vue 的 `provide/inject` 不同，React Context 不会按字段追踪，只按 Provider 的 value 引用判断

### 1.5 生命周期、指令与样式

| Vue | React | 说明 |
|---|---|---|
| `setup` / `created` | 组件函数体 | render 阶段，必须纯 |
| `onMounted` | `useEffect(..., [])` / `useLayoutEffect` | 依赖 DOM 测量用 layout effect |
| `onUpdated` | 无直接对应 | 通常说明状态设计有问题 |
| `onUnmounted` | Effect cleanup | 取消订阅/定时器/请求 |
| `onErrorCaptured` | Error Boundary | 类组件或库实现 |
| `v-if` | `cond && <A />` / 三元 | 注意 `0 &&` 的坑 |
| `v-for` | `arr.map()` + key | key 必须稳定 |
| `v-model` | `value` + `onChange` | 受控组件，单向数据流 |
| `v-show` | `hidden` / CSS | 保留 DOM |
| `v-html` | `dangerouslySetInnerHTML` | XSS 风险 |
| `v-once` | 模块级常量 JSX / `memo` | 无专门指令 |
| 自定义指令 | `ref` + `useEffect` 或封装组件 | 用组合表达行为 |
| `<style scoped>` | CSS Modules / Tailwind / CSS-in-JS | 没有内置作用域样式 |
| `:class` / `:style` | `className` / `style` 对象 | camelCase；className 用字符串拼接 |

### Vue 对照笔记

| Vue | React | 关键差异 |
|---|---|---|
| SFC `<script setup>` | 函数组件 | React 组件就是函数，没有模板 |
| `defineProps` | props 参数 + TS 类型 | props 是渲染快照、只读 |
| `emit('edit', user)` | `onEdit(user)` 回调 prop | 没有 emit，用函数 prop 向上通信 |
| 默认插槽 `<slot />` | `children` | children 是普通 prop |
| 具名插槽 `<slot name="header" />` | `header: ReactNode` prop | 用 props 传 JSX |
| 作用域插槽 `v-slot="{ user }"` | `renderActions: (user) => ReactNode` / 函数 children | render props，渲染期调用且必须纯 |
| `provide/inject` | `createContext` + `useContext` | Context 按 value 引用通知，不按字段追踪 |
| `onMounted` / `onUnmounted` | `useEffect(..., [])` + cleanup | 只有父组件条件挂载才是真卸载 |
| `v-if` | `{cond && <Comp />}` / 三元 | 条件挂载 ≈ v-if；提前 return ≈ v-show |
| `v-model` | `value` + `onChange` | 受控组件、单向数据流 |
| `<style scoped>` | CSS Modules / Tailwind / CSS-in-JS | 没有内置作用域样式 |

总结（5 行）：

- Vue 的组件接口是声明式的（props/emit/slots/provide 各有语法）；React 只有 props。
- UI 片段就是 `ReactNode`；需要携带数据时把 UI 片段变成函数（render prop）。
- Context 只按 Provider value 的引用通知；内联对象每次都是新引用，会让所有消费者重渲染。
- 父组件条件挂载才是真正的挂载/卸载；组件内提前 return 必须在所有 Hooks 之后，否则违反 Hooks 顺序。
- React 的生命周期不是钩子，而是「渲染 → 提交 → 清理」的模型。

### 我的实现 / 遇到的问题

文件结构：

```
src/components/day003/
├── Card.tsx            # header / children / footer
├── UserCard.tsx        # 回调 prop + renderActions
├── ThemeBadge.tsx      # Context 消费者
├── ThemeProvider.tsx   # Provider + useTheme
└── Modal.tsx           # 条件挂载 + Escape + cleanup
```

关键实现：

```tsx
// UserCard：Card 组合 + 作用域插槽
<Card
  header={<div>{user.name}<ThemeBadge /></div>}
  footer={
    <>
      <button onClick={() => onEdit(user)}>edit</button>
      <button onClick={() => onDelete(user.id)}>delete</button>
    </>
  }
>
  {renderActions(user)}
</Card>

// Modal：生命周期与 cleanup
useEffect(() => {
  console.log("[Modal] mount");
  const handleEscape = (e: KeyboardEvent) => {
    if (e.key === "Escape") onClose();
  };
  window.addEventListener("keydown", handleEscape);
  return () => {
    console.log("[Modal] unmount");
    window.removeEventListener("keydown", handleEscape);
  };
}, []);

// App：条件挂载 ≈ Vue v-if
{open && (
  <Modal onClose={() => setOpen(false)}>
    <div>{user.name}</div>
  </Modal>
)}
```

**观察与修复记录**：

- StrictMode 开发环境下打开 Modal，日志为 `mount → unmount → mount`（Effect 首次挂载的 setup→cleanup→setup），关闭时再出现一次 `unmount`。
- 初版 Modal 没有依赖数组、在 setup 里根据 `open` 打印 unmount，已改为父组件条件挂载 + cleanup 打印。
- 初版 `UserCard` 没有用 `Card` 组合、`renderActions` 类型写成 `void`，已修正为 `ReactNode` 并移入 Card 的 children。
- 初版 Context 默认值是带 no-op 的真实对象，守卫永远不触发；已改为 `undefined` + `useTheme` 抛错。
- 遗留观察：`value={{ theme, toggleTheme }}` 每次 Provider 渲染都是新对象，打开/关闭 Modal 也会让 ThemeBadge 重渲染；优化在 Day 017。

## 3. 闭卷自测（10 min）

**得分：6.5 / 10**

**Q1｜Vue → React 组件接口** ✅
`user`、`onEdit`、`header={<h3>{user.name}</h3>}`、`renderActions={(user) => ...}`、children 嵌套，映射全对。

**Q2｜找 bug** ⚠️
给出了正确写法 `onClick={() => onSave("x")}`，但没说明原因。三个问题：
1. `onSave("x")` 在 render 期间立即执行，不是点击时
2. 传进去的是返回值（`void`），点击没有处理函数
3. StrictMode 下 render 双调用 → 每次渲染执行两次；若内部 `setState` 会无限循环

**Q3｜Context** ❌
关键错误：`value={{ theme, toggleTheme }}` **每次 Provider 渲染都是新对象**，即使 theme 没变，`Object.is` 也是 `false`。所以：
1. theme 变化时，**所有**消费者重渲染，不管读了哪个字段
2. Provider 因其他 state 重渲染时，消费者**也会**重渲染
3. Vue 的 provide/inject 依赖响应式系统按属性追踪；React Context 只比较 value 引用，不做字段追踪

**Q4｜挂载与卸载** ✅ 结论对，原因需补：
- `{open && <Modal />}`：真正挂载/卸载，Effect cleanup、state 重置，≈ `v-if`
- 组件内 `if (!open) return null`：组件保持挂载，state 保留、Effect 仍生效，≈ `v-show`
- 若提前 return 写在 `useEffect` 之前：`open=true` 时有 hook、`open=false` 时 hook 数量变少 → 违反 Hooks 固定顺序，报 `Rendered fewer hooks than expected`
- StrictMode 挂载日志：`mount → unmount → mount`

## 4. 总结与复习卡（10 min）

### 今日一句话总结

React 的组件接口只有 props：`emit` 是回调 prop，插槽是 `ReactNode` / 函数 prop，`provide/inject` 是 Context；Context 按 value 引用通知而非字段追踪，真正的挂载/卸载由父组件的条件渲染决定。
